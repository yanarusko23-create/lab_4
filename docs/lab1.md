## ТЕОРЕТИЧНІ ВІДОМОСТІ

### Система керування версіями

**Система керування версіями** (англ. *source code management*, SCM) — програмний інструмент для керування версіями одиниці інформації: вихідного коду програми, скрипту, веб-сторінки, веб-сайту, 3D моделі, текстового документу тощо.

Система керування версіями є потужним інструментом, який дозволяє одночасно, без перешкод один одному, проводити роботу над груповими проєктами. Кожна версія позначається унікальною цифрою чи літерою, зміни документу занотовуються, зберігається автор та час змін.

### Типи систем контролю версій

**1. Централізовані системи контролю версій** (клієнт-серверні) — дані зберігаються у єдиному «серверному» сховищі. Весь обмін файлами відбувається з використанням центрального сервера.

*Переваги:*
- загальна нумерація версій;
- дані містяться на одному сервері;
- можлива реалізація функції блокування файлів;
- можливість керування доступом до файлів.

*Недоліки:*
- необхідність мережевого з'єднання для оновлення робочої копії чи збереження змін.

*Приклади:* Subversion, Team Foundation Server.

**2. Розподілені системи контролю версій** (англ. *Distributed Version Control System*, DVCS) — використовують замість моделі клієнт-сервер розподілену модель зберігання файлів. Такі системи не потребують сервера, адже всі файли знаходяться на кожному з комп'ютерів.

*Переваги:*
- кожний з розробників працює зі своїм власним репозиторієм;
- рішення щодо злиття віток приймається керівником проєкту;
- немає потреби в постійному мережевому з'єднанні.

*Недоліки:*
- немає можливості централізованого контролю доступу до файлів;
- відсутня загальна нумерація версії файлу;
- значно більша кількість необхідного дискового простору;
- немає можливості блокування файлів.

*Приклади:* Git, Mercurial, SVK, Monotone, Codeville, BitKeeper.

### Основні терміни

- **Транк** (trunk) — основна гілка коду;
- **Бранч** (branch) — відгалуження від основної гілки;
- **Чекін** (check in, submit, commit) — відправлення коду в репозиторій;
- **Чекаут** (check out) — одержання змін з репозиторію;
- **Конфлікти** — виникають, коли кілька людей одночасно правлять один і той же фрагмент коду;
- **Патч** (patch) — фрагмент із записаними змінами, які можна застосувати до сховища з кодом.

### Основні команди Git

| Команда | Призначення |
|---------|-------------|
| `git init` | Створення нового локального репозиторію |
| `git clone <url>` | Клонування існуючого репозиторію з віддаленого сервера |
| `git status` | Перегляд стану файлів у робочій директорії та індексі |
| `git add <file>` | Додавання файлу до індексу (staging area) |
| `git commit -m "msg"` | Створення коміту з повідомленням |
| `git push` | Надсилання локальних змін на віддалений сервер |
| `git pull` | Отримання та злиття змін з віддаленого сервера |
| `git fetch` | Отримання змін без злиття |
| `git branch` | Робота з гілками (перегляд, створення) |
| `git checkout` | Переключення між гілками або відкат файлів |
| `git merge` | Злиття гілок |
| `git log` | Перегляд історії комітів |

### GitHub

**GitHub** — хмарний хостинг репозиторіїв Git із додатковими можливостями для співпраці: Issues, Pull Requests, Code Review, Actions (CI/CD), GitHub Pages тощо.

*Переваги GitHub:*
- простий спосіб реєстрації;
- адаптовані клієнти для всіх популярних ОС;
- проста синхронізація між сервісом та локальною версією;
- підтримка багатьох мов програмування;
- можливість відновлення репозиторію після видалення.

### Pull Request

**Pull Request (PR)** — механізм пропозиції змін до репозиторію. Розробник у власній гілці робить зміни, після чого створює запит на злиття з основною гілкою. Інші учасники команди (рев'юєри) переглядають зміни, залишають коментарі та схвалюють (Approve) або відхиляють (Request changes) запит. Після отримання необхідних схвалень PR можна злити (merge) у цільову гілку.
